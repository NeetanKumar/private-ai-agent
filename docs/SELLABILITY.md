# What Would Make This Sellable

One line each. Ranked by what blocks a sale, not by effort.

1. **Declassification.** A supervised way to redact and downgrade a fragment from PRIVATE to CLEAN, or the frontier lane stays permanently dead after the first real use.
2. **Proof, not claims.** Run the host-level checks for real, and add a tamper-evident audit log, so "private data cannot leak" is evidenced rather than asserted.
3. **Connectors to where data lives.** Ingest from email, shared drives, chat and ticketing systems while preserving the source label, since nobody's data sits in a plain folder.
4. **An administrator's view.** Single sign-on, groups, per-team isolation, and a console of who asked what and what was blocked, since "adding a user is a config edit" fails past a handful of users.
5. **An install anyone can do.** A prebuilt machine image or one script, plus a health page in plain words, since one guided session here still hit three separate faults.
6. **A compliance pack.** A data flow diagram, a security whitepaper, a data processing agreement template and a subprocessor list, since their absence stalls deals at the legal stage.

## The harder question

The moat is thin: the taint engine itself could be rebuilt in weeks. The real asset is the test suite, the twelve-document injection corpus, and the documented honesty about what is unverified. Lead with that, not the routing logic. Fits an open-core model: paid connectors, support and the compliance pack, since the gateway is the copyable part.

It is currently called a template, and templates do not sell. It needs a name and a claim.
